# Phase 2: Solution Engineering – Part 2

## Algorithm / Agent Design: Gap Analysis Agent

### Objective

The Gap Analysis Agent is responsible for identifying regulatory gaps, control deficiencies, missing evidence, overdue obligations, and operational risks based on the compliance assessment records generated by the **Compliance Evaluation Agent**. Unlike the Compliance Evaluation Agent, which determines the compliance status of individual tasks, the Gap Analysis Agent determines what remains unresolved, what poses regulatory risk, and what corrective actions should be prioritized. The output of this agent enables management-level compliance monitoring, remediation planning, and regulatory inspection readiness.

### Role in the Overall Architecture

The SEBI problem statement emphasizes proactive compliance management and early identification of regulatory risks before inspections or enforcement actions occur. The Gap Analysis Agent transforms individual compliance evaluation results into a **risk-oriented remediation view**, allowing compliance officers and senior management to understand where compliance failures exist, why they occurred, and how they should be addressed. It receives compliance assessment records from the Compliance Evaluation Agent and produces structured gap records and management summaries that are passed to the Audit Report Agent.

Pipeline transition:

`Compliance Evaluation Agent → Gap Analysis Agent → Audit Report Agent`

### Document Analysis Findings

Analysis of the uploaded SEBI Master Circular revealed several operational and governance patterns that directly influenced the design of the Gap Analysis Agent.

#### Control-Oriented Regulatory Framework

The SEBI Master Circular requires stock brokers to maintain internal controls, conduct audits, implement cybersecurity measures, preserve records, manage investor grievances, submit regulatory reports, and maintain governance mechanisms. These requirements indicate that compliance gaps often represent weaknesses in **operational controls rather than isolated task failures**.

#### Systemic Nature of Non-Compliance

A missing audit report may indicate:

* failure to conduct the audit,
* failure to document the audit,
* failure to retain records,
* failure of ownership,
* failure of governance oversight.

Similarly, repeated overdue reporting tasks may indicate a recurring process failure within a department. The agent therefore evaluates **patterns of recurring non-compliance** in addition to individual failures.

#### Variable Regulatory Impact

Not all compliance gaps carry the same regulatory consequence. For example:

* missing website disclosures,
* delayed investor complaint resolution,
* absent system audit reports,
* missing cybersecurity incident reporting,
* failure to maintain client records.

Each gap should therefore be assigned a **risk severity level** to support remediation prioritization.

#### Deadline-Driven Exposure

The SEBI Master Circular contains numerous time-bound obligations, including requirements to act within seven working days, fifteen working days, monthly, quarterly, half-yearly, or annually. Any missed deadline creates immediate regulatory exposure and should be treated as a priority gap.

#### Evidence Deficiency vs. Operational Failure

A compliance task may be operationally completed while lacking documentary evidence. For example:

* a complaint may have been resolved without uploading proof,
* an audit may have been conducted without preserving the report,
* a disclosure may have been published without retaining a screenshot.

The agent therefore distinguishes between:

* control failures,
* evidence gaps,
* documentation deficiencies,
* process delays,
* governance weaknesses.

#### Management-Level Compliance Visibility

Compliance officers require aggregated insights such as:

* number of non-compliant obligations,
* overdue tasks,
* missing evidence items,
* high-risk clauses,
* affected departments,
* recurring failure areas,
* chapter-wise compliance coverage.

The Gap Analysis Agent therefore generates both **individual gap records and portfolio-level compliance summaries**.

### Inputs

The Gap Analysis Agent receives:

* `document_id`
* Compliance assessment objects
* Obligation metadata
* Task metadata
* Evidence metadata
* Regulatory deadlines
* Clause references
* Page references

### Outputs

The agent generates:

* Structured **Gap Records**
* Department-level gap summaries
* Chapter-level compliance summaries
* Risk distribution summaries
* Remediation recommendations
* Overall compliance coverage metrics

The output status is updated to **GAP_ANALYSIS_COMPLETED**.

### Functional Responsibilities

#### 1. Non-Compliance Identification

The agent identifies obligations classified as **Non-Compliant**, **Partially Compliant**, **Overdue**, or **Pending Review**.

#### 2. Gap Classification

Each identified issue is categorized into a standardized gap type such as:

* Missing Evidence
* Documentation Deficiency
* Overdue Obligation
* Control Failure
* Governance Gap
* Process Delay
* Reporting Failure
* Audit Deficiency

#### 3. Risk Severity Assessment

The agent assigns a regulatory risk level based on:

* legal impact,
* time sensitivity,
* regulatory importance,
* recurrence,
* evidence quality,
* operational criticality.

Risk levels include:

* **Critical**
* **High**
* **Medium**
* **Low**

#### 4. Root Cause Inference

The agent identifies the most probable cause of the compliance gap, such as:

* missing documentation,
* delayed submission,
* ownership failure,
* inadequate controls,
* process breakdown,
* governance deficiency.

#### 5. Corrective Action Recommendation

For every gap, the agent generates a recommended remediation action.

Examples:

* upload missing audit report,
* submit overdue regulatory filing,
* update website disclosures,
* complete investor complaint resolution,
* implement evidence retention process,
* strengthen internal control procedure.

#### 6. Department-Level Aggregation

Gaps are grouped by operational ownership areas such as:

* Compliance
* Operations
* Information Technology
* Information Security
* Finance
* Legal
* Client Onboarding

This allows management to identify departments with concentrated compliance exposure.

#### 7. Regulatory Chapter Analysis

The agent aggregates gaps according to the originating SEBI chapter or regulatory domain (audit, grievance, cybersecurity, reporting, governance, etc.) to identify high-risk regulatory areas.

#### 8. Compliance Coverage Calculation

The agent computes overall compliance coverage metrics, including:

* compliant obligations,
* partially compliant obligations,
* non-compliant obligations,
* overdue obligations,
* evidence completeness,
* chapter-wise compliance percentage.

### Processing Algorithm

The Gap Analysis Agent operates using the following workflow:

1. Receive compliance assessment records.
2. Identify non-compliant and partially compliant obligations.
3. Detect overdue obligations.
4. Detect missing or incomplete evidence.
5. Classify each gap type.
6. Assess regulatory risk severity.
7. Infer probable root cause.
8. Generate corrective action recommendations.
9. Aggregate departmental summaries.
10. Aggregate chapter-level summaries.
11. Compute compliance coverage metrics.
12. Store gap records and summaries.
13. Update document status to **GAP_ANALYSIS_COMPLETED**.

### Structured Output Model

Each Gap Record contains:

* `gap_id`
* `evaluation_id`
* `gap_type`
* `risk_severity`
* `root_cause`
* `recommended_action`
* `owner_department`
* `clause_reference`
* `page_number`
* `status`

In addition, the agent generates summary objects containing:

* total gaps,
* gaps by severity,
* gaps by department,
* gaps by regulatory chapter,
* overall compliance percentage.

These outputs become the direct input for the Audit Report Agent.

### State Transition

Document lifecycle after gap analysis:

`COMPLIANCE_EVALUATED`
↓
`GAP_ANALYSIS_COMPLETED`
↓
`HANDOFF TO AUDIT REPORT AGENT`

### Error Handling

| Failure Scenario                     | System Action                                     |
| ------------------------------------ | ------------------------------------------------- |
| Missing compliance assessment record | Skip record and log anomaly                       |
| Conflicting compliance statuses      | Escalate for human review                         |
| Missing department mapping           | Assign Compliance Department                      |
| Unknown severity level               | Default to Medium                                 |
| Recommendation generation failure    | Provide generic remediation guidance              |
| Summary aggregation failure          | Generate partial summary and flag analytics error |

### Time Complexity

For **E compliance assessment records**:

* Status analysis: **O(E)**
* Gap classification: **O(E)**
* Severity scoring: **O(E)**
* Summary aggregation: **O(E)**

The overall gap analysis process is **linear with the number of evaluated compliance tasks**, making it suitable for enterprise-scale compliance portfolios.

### Design Rationale

The SEBI Master Circular is fundamentally organized around **operational control requirements**, meaning compliance failures often indicate broader control weaknesses rather than isolated task failures. Therefore, the Gap Analysis Agent is designed as a **regulatory risk assessment engine** that aggregates task-level compliance results into department-level, chapter-level, and enterprise-level compliance insights. By distinguishing control failures, evidence gaps, documentation deficiencies, process delays, and governance weaknesses, the agent provides actionable intelligence for remediation planning, management dashboards, regulatory inspection readiness, and audit reporting while preserving complete traceability to the originating SEBI clause and page number.

### Conclusion

The Gap Analysis Agent transforms individual compliance assessment records into structured regulatory gap records and enterprise-level compliance insights. By identifying unresolved obligations, assessing regulatory risk, determining root causes, recommending corrective actions, and generating aggregated compliance summaries, the agent provides the decision-support layer required for proactive compliance management, remediation planning, and regulatory audit readiness within the RegTrace architecture.
