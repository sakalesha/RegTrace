# Phase 2: Solution Engineering – Part 2

## Algorithm / Agent Design: Obligation Extraction Agent

### Objective

The Obligation Extraction Agent is responsible for identifying and extracting actionable compliance obligations from the structured clause objects generated by the Clause Segmentation Agent. It converts legal provisions contained in the **SEBI Master Circular for Stock Brokers** into structured obligation records that represent mandatory actions, prohibitions, conditional requirements, reporting obligations, record-keeping duties, and time-bound compliance requirements. These obligation records form the foundation for automated task generation, evidence collection, compliance monitoring, and audit reporting.

### Role in the Overall Architecture

The SEBI problem statement requires transforming regulatory text into **machine-actionable compliance logic**. The Obligation Extraction Agent performs the core legal reasoning step within the RegTrace architecture by distinguishing enforceable obligations from definitions, explanations, references, and background information. It receives a collection of **SEGMENTED** clause objects from the Clause Segmentation Agent and produces structured obligation objects that are passed to the Task Generation Agent.

Pipeline transition:

`Clause Segmentation Agent → Obligation Extraction Agent → Task Generation Agent`

### Document Analysis Findings

Analysis of the uploaded SEBI Master Circular revealed several linguistic and structural patterns that directly influenced the design of the Obligation Extraction Agent.

#### Mandatory Regulatory Language

The circular repeatedly uses imperative legal expressions such as:

* “Stock Brokers shall…”
* “Stock Exchanges shall ensure…”
* “The intermediary shall submit…”
* “The broker shall maintain…”

These expressions clearly indicate mandatory regulatory obligations and represent the primary trigger for obligation extraction.

#### Prohibition Clauses

The circular also contains restrictions expressed through phrases such as:

* “shall not”
* “must not”
* “shall not permit”
* “shall not engage”

These represent negative obligations and must be classified separately from affirmative compliance requirements.

#### Time-Bound Compliance Requirements

Many clauses specify explicit deadlines and compliance timelines, including:

* within twenty-four hours
* within seven working days
* within fifteen working days
* immediately upon occurrence
* before commencement

These temporal expressions are essential for automated compliance monitoring and deadline tracking.

#### Responsible Entity Identification

Obligations are assigned to different regulated entities, including:

* Stock Broker
* Stock Exchange
* Clearing Corporation
* Depository
* Compliance Officer
* Designated Person
* Authorized Person

The responsible entity must be extracted for every obligation so that tasks can later be assigned to the appropriate operational owner.

#### Conditional Obligations

Numerous obligations apply only under specific circumstances, for example:

* where applicable
* if the client requests
* in case of default
* whenever a complaint is received

These conditions must be preserved because they determine when the obligation becomes enforceable.

#### Multiple Obligations within a Single Clause

A single regulatory clause frequently contains more than one independent compliance requirement, such as maintaining records, submitting reports, preserving documents, and notifying the Stock Exchange.

Therefore, one clause may generate multiple obligation records.

### Inputs

The Obligation Extraction Agent receives:

* `document_id`
* Structured clause objects from the Clause Segmentation Agent
* Clause hierarchy
* Page references
* Regulatory references

### Outputs

The agent generates a collection of structured **Obligation Objects**, each containing:

* Obligation ID
* Clause ID
* Document ID
* Responsible entity
* Action
* Object of the action
* Obligation type
* Deadline
* Frequency
* Condition
* Page number
* Clause reference
* Confidence score
* Processing status

The output status is updated to **OBLIGATIONS_EXTRACTED**.

### Functional Responsibilities

#### 1. Obligation Trigger Detection

The agent identifies mandatory and prohibitory legal expressions using a combination of rule-based patterns and language-model reasoning.

Primary trigger expressions include:

* shall
* shall ensure
* shall maintain
* shall submit
* shall designate
* shall not
* must
* must not
* is required to

#### 2. Responsible Entity Extraction

The agent identifies the regulated entity responsible for performing the obligation.

Examples:

* Stock Broker
* Stock Exchange
* Clearing Corporation
* Depository
* Compliance Officer

#### 3. Action Extraction

The agent extracts the core compliance action that must be performed.

Examples:

* maintain records
* submit reports
* designate a compliance officer
* notify the Stock Exchange
* preserve documents

#### 4. Object Extraction

The agent identifies the object associated with the action.

Examples:

* client records
* periodic reports
* investor complaints
* bank account details
* audit reports

#### 5. Obligation Classification

Each extracted obligation is classified into one of the following categories:

* **Mandatory**
* **Prohibition**
* **Conditional**
* **Reporting**
* **Record Keeping**
* **Operational**
* **Monitoring**
* **Notification**

#### 6. Deadline and Frequency Extraction

The agent extracts temporal expressions and reporting frequencies associated with the obligation.

Examples:

* within seven working days
* monthly
* quarterly
* annually
* immediately

#### 7. Condition Extraction

The agent captures qualifying conditions that determine when the obligation becomes applicable.

Examples:

* if the client requests
* where applicable
* in case of default
* whenever a complaint is received

#### 8. Multi-Obligation Resolution

When a single clause contains multiple independent compliance requirements, the agent generates a separate obligation object for each requirement while preserving the same clause reference.

### Processing Algorithm

The Obligation Extraction Agent operates using the following workflow:

1. Receive segmented clause objects.
2. Detect obligation trigger phrases.
3. Identify the responsible entity.
4. Extract the action phrase.
5. Extract the object phrase.
6. Extract deadlines and frequencies.
7. Extract conditions and exceptions.
8. Classify the obligation type.
9. Generate one or more structured obligation objects.
10. Store obligation records.
11. Update document status to **OBLIGATIONS_EXTRACTED**.

### Structured Output Model

Each Obligation Object contains:

* `obligation_id`
* `clause_id`
* `document_id`
* `subject`
* `action`

This structured representation becomes the direct input for the Task Generation Agent.

### Error Handling

| Failure Scenario                    | System Action                                      |
| ----------------------------------- | -------------------------------------------------- |
| Ambiguous responsible entity        | Inherit entity from parent clause                  |
| Multiple actions in one sentence    | Split into multiple obligation objects             |
| Missing deadline                    | Store deadline as null                             |
| Uncertain obligation classification | Assign low confidence score and flag for review    |
| Language model extraction failure   | Retry extraction and queue for human review        |
| Incomplete clause text              | Preserve raw clause and mark extraction incomplete |

### Time Complexity

For **M segmented clause objects**:

* Trigger detection: **O(M)**
* Entity extraction: **O(M)**
* Action extraction: **O(M)**
* Metadata extraction: **O(M)**

The overall obligation extraction process is **linear with the number of segmented clauses**, making it suitable for large regulatory documents such as the SEBI Master Circular.

### Design Rationale

The SEBI Master Circular expresses regulatory obligations using highly standardized legal language, particularly through repeated use of modal verbs such as **shall**, **shall ensure**, **shall maintain**, **shall submit**, and **shall designate**. The Obligation Extraction Agent is therefore designed as a **hybrid rule-assisted language-model pipeline**, where deterministic rules identify obligation-bearing clauses and legal entities, and the language model converts those clauses into structured compliance records. This hybrid approach improves extraction accuracy, reduces hallucination risk, and preserves complete traceability between every obligation and its originating clause and page within the SEBI Master Circular.

### Conclusion

The Obligation Extraction Agent transforms segmented legal clauses from the SEBI Master Circular into structured, machine-actionable compliance obligations. By identifying responsible entities, mandatory actions, prohibitions, deadlines, frequencies, conditions, and regulatory references, it creates the standardized compliance knowledge base required for automated task generation, evidence collection, compliance evaluation, and audit-ready regulatory traceability throughout the RegTrace architecture.
